# Cybercrime Records Program

Make Records systematic. You register risks, design layered controls, train every tier, audit with evidence, remediate dated gaps, and report posture upward — preventing what you can, detecting the rest.

Optimize simultaneously for:

- known risks
- layered controls
- trained org
- audited posture
- informed leaders

Records advises and assures; business owns risks; audit independence respected. Not legal advice.

## Use Cases

### Program build

Trigger: user says 'start Records' or 'get compliant'

Steps:

1. Register risks
2. Design controls
3. Train + audit
4. Report + improve

Result: Living program.

### Audit season

Trigger: user says 'external audit' or 'prove controls'

Steps:

1. Evidence gather
2. Walkthroughs
3. Remediate fast
4. Close clean

Result: Passed audit.

### Gap sprint

Trigger: user says 'too many findings' or 'fix fast'

Steps:

1. Prioritize risk
2. Sprint fixes
3. Verify closed
4. Prevent repeat

Result: Cleaner posture.

Ask yourself before starting:

- What is the smallest verifiable outcome the user needs?
- What evidence will prove the result is correct?
- Which failures are most likely, and how will each be detected?
- What scope, budget, or policy constraints apply?
- What artifact must remain for audit or reuse?

## Core Output Requirements

Every delivery with this skill must include:

- Risk register
- Control matrix
- RACI
- Training plan
- Audit reports
- Remediation log
- Metric pack
- Board minutes

Never run Records on vibes or let findings rot without owners and dates.

## Phase 1 — Register Risks

20+ cyber-law risks rated + owned.

Review quarterly.

Top risks to leadership.

## Phase 2 — Design Controls

Preventive/detective/corrective per risk.

Score with `scripts/control_audit.py`.

RACI each control.

## Phase 3 — Train and Audit

Tiered training + tested.

Control audits evidenced.

Findings owned + dated.

## Phase 4 — Report Up

Quarterly posture pack.

Decisions requested explicit.

Minutes filed.

## Troubleshooting

### Training theater

Cause: Click-through courses

Fix:

1. Role-based + tested
2. Phishing/tabletops
3. Consequences
4. Measure behavior

### Audit dread

Cause: Evidence scramble

Fix:

1. Continuous evidence
2. Control owners
3. Pre-audits
4. Calm season

### Board blindness

Cause: No reporting

Fix:

1. Quarterly pack
2. Top risks + asks
3. Minutes
4. Follow-through

## Decision Heuristic

Before adding complexity, ask:

1. What outcome requires this step?
2. What evidence justifies it?
3. What happens when it fails?
4. What is the cheaper alternative?
5. What proves quality did not regress?
6. What must be logged for audit?
7. What is the rollback plan?

If the main justification is "more", prove the outcome needs it first.

## Anti-Patterns

Avoid register-free risk; control-free hopes; theater training; evidence-free audits; finding rot; board-blind ops.
